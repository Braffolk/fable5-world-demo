# S3 / CloudFront layout

`data/out/` mirrors the bucket exactly — deploy with a single sync:

```sh
# immutable content-hashed objects: safe to upload additively, cache forever
aws s3 sync data/out/c   s3://$BUCKET/laas/c   --cache-control "public,max-age=31536000,immutable"
aws s3 sync data/out/m   s3://$BUCKET/laas/m   --cache-control "public,max-age=31536000,immutable"
# the one mutable pointer, uploaded LAST to flip the release atomically:
aws s3 cp   data/out/latest.json s3://$BUCKET/laas/latest.json --cache-control "public,max-age=30"
```

Client boot: GET `latest.json` -> GET `m/<hash>/manifest.json` -> GET `m/<hash>/index/<layer>.bin`
-> stream `c/<layer>/<lod>/<cx>_<cz>.<hash8>.bin` as the camera moves.

- Chunk objects are named by content hash and never mutated, so CloudFront TTL = 1 year and
  `aws s3 sync` only uploads genuinely new chunks between releases.
- A new cook that changes any chunk writes a new manifest hash; `latest.json` (30 s TTL) flips
  the whole world atomically. Old manifests stay live for rollback.
- CORS: allow `GET` from the game origin; `Access-Control-Allow-Origin` on the bucket/distribution.
