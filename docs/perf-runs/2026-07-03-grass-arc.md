## THE REBUILD (2026-07-03, session 2) — procedural zero-storage blade field

Design (committed before implementation; "GoT-on-nanite", explores past the plan's S7):

- **Zero storage, zero boot cost.** No patches, no instances, no DAGs, no bootcache. A fused
  cull+raster COMPUTE kernel re-derives every clump from `pcg(worldCell)` per frame, using the
  GroundRing density/thin×widen/band laws VERBATIM (that system IS the user's lushness
  reference). Toroidal fine grid 3072²@0.105 m (±161 m, ~90 slots/m², 5-blade clumps) + coarse
  super-tuft grid 768²@0.7 m (150–265 m); terrain splat beyond. Works at any world size.
- **Self-describing 30-bit blade ids, no work queue.** Election id = `0xC0000000 | body`
  (bit31|bit30 — collision-free: voxels are bit31 with bits 28-30 zero, mesh ids reach bit30
  only past itemIdx 2^22 which QRASTER never sees at the default 128-tri config where ids are
  ≤30 bits). body = slot(24b)<<6 | prim(3b)<<3 | seg(2b)<<1 | tri(1b); far tufts in a reserved
  range above FAR_BASE. The resolve re-derives the exact corner positions from the id
  (makeCtx-precedent bit-identity: same expression tree ⇒ same f32), interpolates via the
  existing baryWeights(wp,·) idiom, and runs the S0 grass shading port.
- **Raster seams reused 1:1.** Small quads → the fixed-point SW scanline (top-left rule,
  depthKey24 guarded atomicMax election into visPayloadV/visBV — same emit as mesh/vox);
  near/oversized/near-plane-crossing quads → a grass HW queue drawn inside the SAME hwRender
  pass (own indirect draw, vertex stage re-derives corners, fragment clones the world1
  election). Kernels ride world1's existing batched submit (after kVisClear, before kHwArgs)
  — zero extra submits.
- **LOD is continuous + spatially jittered, no bands, no checkerboard by construction.**
  thin×widen conserves coverage (ring law); 5→3 blades ~30 m, 4→2→1 segs, blades→cards ~70 m —
  every transition per-clump hash-jittered in WORLD space (replaces the ring's screen-space
  IGN crossfade). All representations sample the same analytic blade curve so seg-count
  switches are sub-pixel at their trigger distance.
- **Shading**: grass pixels shade in the vox-side resolve pass ('both' in forest, 'vox' in
  world) — matClass forced 255 for grass px so no mesh subgraph runs; S0 ramps/terrain-pull/
  tip-AO/backlight preserved; PCSS receive/GTAO/TRAA/water automatic via the shared election.
- Old patch-DAG lane demoted to `?grasspatch=1`; new lane default-on, `?grass=0` escape +
  `__laasNanite.setGrass(0|1)` runtime A/B for within-session perf gating.

### Rebuild session log (2026-07-03, session 2) — SHIPPED CHECKPOINT + measured state

Correctness bugs found on bring-up (booked for reuse):
1. **Nested unnamed TSL loops collide on `i`** — the outer counter read inside the inner
   body silently resolves to the inner one; only diagonal prim==seg quads emitted
   ("stubs + floating fragments"). Fix: `loopUN` (named uint loop) in Tsl.ts; ANY nested
   Loop must name its vars.
2. **A single f32 varying cannot carry a >2^24 id** — the 30-bit grass body id rounds;
   split lo/hi 16-bit varyings (the mesh HW path's vPayLo/vPayHi idiom).
3. **toF() on a uint select-chain got DROPPED in the fragment build** (WGSL f32/u32 parse
   error) — build float selects directly (ladder segNF).
4. **Blades must root on the DISPLACED terrain** (heightTex + terrainDispAt — factored out
   of hfWorld into an export): raw-height roots sink up to ~0.15 m (DISP.base) into the
   near-field relief. The resolve ALSO needs disp for the analytic t (±0.15 m ⇒ t±0.5).
5. **WebGPU forbids read-only+writable views of one buffer in ONE render pass** — the
   early-z depth prime (reads payloadV) and the blade election (writes it) need two
   passes over the shared depth target.

Perf findings (grass2-ab/split/swtest, world eye meadow + 45 m oblique, dpr 1.5,
within-boot setGrass A/B, medians):
- Attribution: cull funnel ≈ 1 ms; clump derive + corner math ≈ free; the cost is
  FRAGMENTS. The compute SW scanline is ~10× costlier per fragment than the HW raster
  (serial per-thread pixel walk vs packed hardware): swpx 4/16/24 ⇒ grass compute
  3.4/15.7/18 ms while the HW pass barely moves. **Default routed: SW keeps only ≤4 px
  slivers, everything else rides the grass HW queue (kernel-computed corners packed in
  the queue, stride-10 f32; vertex stage = pure unpack).**
- Grass HW pass got its own depth target with a fullscreen election-depth PRIME +
  depth-tested blades (hardware early-z; two passes per the WebGPU usage rule).
- Resolve reconstructs shading ANALYTICALLY (t = (wp.y−rootY)/bladeH, per-prim mean
  normal, ≤40 m; beyond = const tip + terrain normal) — no corner re-derivation.
- **CHECKPOINT NUMBERS (eye meadow / oblique, dpr 1.5): grass total ≈ +13 / +7-19 ms**
  (compute Δ4.4, r.grass.hw 5.6, r.scene Δ1.7, r.half.mrt Δ2 at eye; oblique thermally
  noisy). Visual: reference-parity lushness at all ladder distances, zero grid/
  checkerboard/banding. **PERF MANDATE NOT YET MET (target ≤ ~+2.5 eye / +1 typical).**
- Known limit (user-flagged): HW queue caps at 1.5M tris (60 MB) — an open eye-level
  meadow measured 1.42M; bigger meadows would drop blades.
