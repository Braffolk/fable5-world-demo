## W3a — SNAPSHOT DEDUP (the fix; 30 copies → 2)

ROOT CAUSE (three source, ViewportTextureNode.js + NodeFrame.js): viewport nodes
share the TEXTURE but dedupe `updateBefore` per NODE INSTANCE (`updateReference()`
returns `this`), and each viewportDepthTexture call site clones per-target textures
per instance. The shipped material has 2 color + 3 depth instances × 6 level
materials ⇒ **measured 12 color + 18 depth full-screen copies PER FRAME** (in-page
`copyFramebufferToTexture` wrap, lake pose).

FIX (`WaterSurface.ts` + `WaterMaterial.ts`): one `FramebufferTexture` + one
`DepthTexture` owned by WaterSurface, copied ONCE per frame in the first-drawn
sheet's `onBeforeRender` (frame-id guard; same mid-pass point three's own machinery
uses); all six materials sample the plain shared textures. Legal because the level
sheets never overlap (inner-rect cutouts) — every sheet wants the pre-water opaque
frame. Legacy slate gets the same path (class-level change).

- Copy count after: **1 color + 1 depth per frame** (was 12+18).
- Shot identity vs pre-fix W1 shots: stream-obl 0.657 / graze 1.161 / shore 0.838 /
  lake-obl 0.992 mean, frac>48 ≤ 0.068% — D0 still-pair family. stream-obl 57→77 fps.
- Within-session A/B after (clean session, drift ≤0.2 all legs):
  **eye +0.1, oblique +0.6, aerial +0.4, lakegraze +2.1, lakeobl +3.0 ms** (was
  +4.0/+2.6/+6.3/+6.4). Fixed adders inside the plan's ≤1.0 cap; heavy-water poses
